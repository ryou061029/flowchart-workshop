# フローチャート工房 仕様・設計

- 作成日: 2026-10-05
- 版: v1.0(2026-10-05 実装・テスト済み。2026-10-06 公開用に単体の HTML へ作り替え、画面の下の表記と自動公開を加えた)
- 位置づけ: 一般公開するブラウザゲームの仕様
- 前の版: v0.2.1(個人の試作)からの作り直し。盤面の読み取りエンジン、画面の操作、アクセシビリティ、確認用サーバー、テストの仕組みは引き継ぐ
- 【暫定】と書いた数値は、初めて遊ぶ人の試遊で調整する

## 1. 目的

カードを方眼の盤面に並べてプログラムの流れを組み立て、お題どおりに動くかをテストで確かめるパズル。
プログラミングを知らない人が、代入・条件・くり返しの考え方を手で触って覚えられるようにする。
1 人で、ブラウザだけで、1 問数分から遊べる。

## 2. 遊び方(モード)

| モード | 内容 | 評価 |
|---|---|---|
| 練習 | 2 問。カードの置き方と盤面の読み方を覚える | なし |
| フリー | 本編 10 問を好きな順に 1 問ずつ解く。使えるカードは課題ごとに決まった種類を、枚数の制限なく使える | 課題ごとに ★ 3 つ |
| チャレンジ | 本編の課題 3 問を決まった順に続けて解く「セット」が 3 種類。セットごとに枚数の決まった手札が配られ、正解した課題に置いたカードは次の課題で使えない | セットごとに ★ 3 つ |

- 制限時間で打ち切ることはしない。経過時間を表示し、評価の基準に使う
- どの課題・セットも最初から遊べる(解放の順番は設けない)

## 3. カード

### 3.1 種類

命令や流れを表すカードは、英語のラベルを大きく書き、その下に日本語の意味を小さく添える。

| 種類 | カード | 日本語の添え字 | 使い方 |
|---|---|---|---|
| はじまりとおわり | Start / End | はじめ / おわり | Start は盤面に 1 枚だけ。End で道が終わる |
| 条件 | IF / Yes / No | もし / はい / いいえ | `IF 式 比較 式` の行のすぐ下に、Yes と No を置く |
| 比較 | `==` `<` `>` | `==` だけ「等しい」 | 条件の中だけで使う。等しい / 小さい / 大きい |
| 出力 | PRINT | 出力 | `PRINT ◯ ◯ …` の形で、後ろに並べたものをつなげて 1 行出す |
| 代入 | `=` | 入れる | `変数 = 式` の形で、右の値を左の変数に入れる |
| 演算子 | `+` `−` `×` `÷` `%` | なし | ÷ は小数点以下を切り捨て、% は割った余り |
| 入力 | INPUT | 入力 | テストケースごとに与えられる数 |
| 変数 | a / b / c | なし | 値を入れておく箱 |
| 数字 | 課題ごとに配る(例: 10、60、1000) | なし | 1 枚で 1 つの数を表す |
| ことば | 課題ごとに配る(例: 円、分、秒、A) | なし | PRINT の中だけで使う文字 |
| くり返し | LOOP / CONTINUE / BREAK | くり返し / もどる / ぬける | CONTINUE で LOOP の直後へ戻り、BREAK でくり返しを抜けてそのカードの下へ進む |

- 英語の表記の決まり: 命令の語は全部大文字(IF・PRINT・INPUT・LOOP・CONTINUE・BREAK)、流れの目印は先頭だけ大文字(Start・End・Yes・No)
- 記号のうち、取り違えやすい `=`(入れる)と `==`(等しい)にも意味の添え字を付ける。ほかの記号・変数・数字・ことばには付けない
- フリーで使えるカード = 共通カード(Start・End・IF・Yes・No・比較 3 種・PRINT・`=`・演算子 5 種・INPUT・a b c・LOOP・CONTINUE・BREAK)+ その課題の数字とことば
- カードの幅(マス数、1 マスは 34px)は、英語のラベルと日本語の添え字の長いほうで決める。数字は 2 けたまで 1 マス、3 けた以上は 2 マス。`=` と `==` は添え字が入るよう 2 マス
- ルール説明・ヒント・お題の文は日本語で書き、カードは添え字の語(もし・出力・入力 など)でも呼ぶ。読み上げ用のラベルは「IF(もし)」のように両方を読む

### 3.2 見た目

見本: `generated/docs/flowchart-kobo-card-design.html`(仲間ごとの一覧と、正解例を盤面に置いた例。ライト / ダークを切り替えて見られる)

- 形は流れ図の記号(JIS X 0121)に寄せる。Start / End = 端子(両端が丸い形)、IF = 判断(ひし形の左右を伸ばした形)、PRINT = 表示(平行四辺形)、LOOP = ループの始まり(上の角を落とす)、CONTINUE・BREAK = ループの終わり(下の角を落とす)。Yes・No・ことば・式の部品は角を丸めた長方形の札

- 式の部品は書体でも見分ける(変数は斜体、数字と INPUT は等幅、記号は太字)
- 日本語の添え字は英語のラベルの下に置き、10.5px(目安 10px 以上)にする。カードの高さは 50px(添え字を入れるため、前の版の 44px から上げる)
- カードの上に種類名を小さく書く表記はしない。種類は形と手札の見出しで伝える

## 4. 盤面の読み取りルール

盤面は 26 列 × 16 行の方眼。カードはマスにぴったり止まる。

1. **命令**: 同じ行で、すき間なく横に並んだカードの並びを 1 つの命令として読む
2. **Start**: 盤面に 1 枚だけ置き、単独で 1 行を使う。その下の行から読み始める
3. **下へ進む**: 次の命令はすぐ下の行に置く。1 行空くと、その道はそこで終わる
4. **条件**: `IF 式 比較 式` の行のすぐ下の行に Yes と No を置く
   - Yes と No の間のすき間の中央で左右に区切り、それぞれの側の下へ道が分かれる
   - Yes / No の右に続けて命令を置いてもよい(その行が道の最初の命令になる)
   - 片方だけ置いてもよい(置かなかった側に進んだときは、そこで道が終わる)
   - 分かれた道は合流しない
5. **End**: End に着いたら終了。道が途中で尽きた場合も、その道より下の行に End が 1 枚でもあれば終了とみなす(End を一番下に 1 枚だけ置く並べ方を認める)
6. **くり返し**: CONTINUE に着いたら LOOP の直後へ戻る。BREAK はくり返しを抜けて、そのカードの下へ進む。LOOP・CONTINUE・BREAK は単独で 1 つの命令(Yes / No の右に続けるのは可)
7. **命令の形**
   - 代入: `変数 = 式`
   - 出力: `PRINT 項 項 …`。項は 変数・INPUT・数字・ことば。並べた順につなげて 1 行出す(例: `PRINT a 分 b 秒` → 「1分15秒」)
   - 条件: `IF 式 比較 式`。比較カードは 1 枚だけ
   - 式: 値(変数・INPUT・数字)と演算子を交互に並べたもの
8. **計算**: × ÷ % を + − より先に計算し、同じ強さなら左から順に計算する。÷ は小数点以下を切り捨てる(負の数は 0 の方向へ切り捨て)。0 で割るとエラー
9. **エラーとして知らせるもの**(原因のカードを示す): Start が無い・複数、どの命令にもつながっていないカード(End を除く)、同じ行に命令が 2 つ、命令として読めない並び、`=` の左が変数 1 枚でない代入、条件の外での比較カード、PRINT 以外でのことばカード、値が入っていない変数の使用、End にたどり着かない道、10,000 ステップを超える実行

## 5. 課題

### 5.3 正解例(命令の並び)

盤面上の配置は実装時に `engine.js` に書き、ユニットテストで合格を確かめる。各課題に別解を 1 つ以上用意し、考え方の短い説明を付ける。

| 課題 | 正解例 | 別解の方向 |
|---|---|---|
| 練習1 | `a = INPUT × 2` → `PRINT a` | `a = INPUT + INPUT` |
| 練習2 | `IF INPUT < 60` → Yes: `PRINT ふごうかく` / No: `PRINT ごうかく` | `IF INPUT > 59` で左右を入れ替える |
| 1 | `a = 1000 − INPUT` → `PRINT a 円` | 1000 を先に変数に入れてから引く(`b = 1000` → `a = b − INPUT`) |
| 2 | `a = INPUT × 11 ÷ 10` → `PRINT a 円` | `a = INPUT + INPUT ÷ 10` |
| 3 | `a = INPUT ÷ 10 % 10` → `PRINT a` | `a = INPUT % 100 ÷ 10` |
| 4 | `a = INPUT ÷ 10 + INPUT % 10` → `PRINT a` | 十の位と一の位を別の変数に入れてから足す |
| 5 | `a = INPUT ÷ 60` → `b = INPUT % 60` → `PRINT a 分 b 秒` | `b = INPUT − a × 60` / INPUT をいったん変数に入れる(`c = INPUT` → `a = c ÷ 60` → `b = c % 60`) |
| 6 | `IF INPUT < 0` → Yes: `a = 0 − INPUT` → `PRINT a` / No: `PRINT INPUT` | 先に `a = INPUT` としてから a で判定する |
| 7 | `IF INPUT < 50` → Yes: `PRINT C` / No: `IF INPUT < 80` → Yes: `PRINT B` / No: `PRINT A` | `IF INPUT > 79` から調べる |
| 8 | `a = INPUT` → LOOP → `PRINT a` → `IF a == 1` → Yes: BREAK / No: `a = a − 1` → CONTINUE | `IF a < 2` で調べる(数字の 1 を 1 枚節約できる) |
| 9 | `a = 1` → LOOP → `a = a × 2` → `IF a > INPUT` → Yes: BREAK → `PRINT a` / No: CONTINUE | `a = 2` から始め、2 倍する前に比べる |
| 10 | `a = INPUT` → `b = 0` → LOOP → `a = a ÷ 10` → `b = b + 1` → `IF a == 0` → Yes: BREAK → `PRINT b` / No: CONTINUE | `IF a > 0` で左右を入れ替える |

### 5.4 ヒント

- 各課題に 1 つ。いつでも開けるが、開くとその回の「基準時間」の ★ は付かない
- 文面は答えをそのまま書かず、考え方の入口だけを示す

## 6. 評価

### 6.1 フリー

| ★ | 条件 |
|---|---|
| 1 | クリア(全テストケースに合格) |
| 2 | クリアし、盤面のカードが基準枚数以下 |
| 3 | クリアし、基準時間以内で、ヒントを開いていない |

- ★ 2 と ★ 3 は別々に判定する(★ 1 + ★ 3 の 2 つ、もありうる)
- 課題ごとに一番よい記録(★ の組み合わせ、最少枚数、最短時間)を残す。やり直しで記録が下がることはない
- 経過時間は課題を開いた時点から数え、クリアで止まる。課題を離れて戻ると 0 から数え直す

### 6.2 チャレンジ

| セット | 課題(この順) | 手札の仕掛け【暫定】 |
|---|---|---|
| A 計算の組み立て | 1 おつり → 3 十の位 → 5 分と秒 | INPUT が 3 枚しかない。課題 5 では INPUT の値をいったん変数に入れる必要がある |
| B 分かれ道 | 2 税込み価格 → 6 絶対値 → 7 3 段階の評価 | INPUT が 4 枚しかない。課題 6 では INPUT の値をいったん変数に入れる必要がある |
| C くり返し | 8 カウントダウン → 9 2 倍、2 倍 → 10 けた数 | 数字の 1 が 3 枚しかない。どこかで 1 を使わない書き方(課題 8 を `a < 2` で調べる、課題 9 を 2 から始める など)が必要になる |

- 手札は、仕掛けを満たす解き方の組み合わせが少なくとも 1 つ収まる枚数にし、そのうえで数枚の余裕を足す。収まることはユニットテストで確かめる
- 2026-10-05 に、正解例と別解を JS に写して仕掛けを検算済み(A は課題 5 を変数経由にする 1 通り、B は課題 6 を変数経由にする 4 通り、C は 1 を節約する 3 通りが収まる)
- 正解した課題の盤面のカードは手札から減る。あきらめた課題のカードは手札に戻る
- あきらめると、その課題は未クリアのまま次の課題へ進む

| ★ | 条件 |
|---|---|
| 1 | 3 問すべてクリア |
| 2 | 3 問すべてクリアし、最後に残った手札が基準枚数以上【暫定: 仕掛けを満たす最少の解き方で残る枚数】 |
| 3 | 3 問すべてクリアし、合計時間が基準以内(3 問の基準時間の合計)で、ヒントを 1 度も開いていない |

## 7. 画面と操作

| 画面 | 内容 |
|---|---|
| スタート | ゲームの説明(短く)、盤面の読み方、カードの仲間。その下に、練習 2 問の入口、フリーの課題一覧(段階・題名・自分の ★ と最少枚数・最短時間)、チャレンジの一覧(課題の並び・手札の仕掛け・自分の ★)を並べる |
| 課題 | お題、手札、盤面、テストケース、試しに動かす欄、ヒント、経過時間と基準時間、判定する、盤面を片付ける、一覧へ戻る(チャレンジでは あきらめる) |
| クリア | ★ の判定と内訳(枚数 / 基準、時間 / 基準、ヒント)、自分の並べ方、正解例と別解の切り替え表示。練習では ★ を出さない |
| チャレンジ結果 | 3 問の結果、残りの手札、★ の判定 |

- フリーで課題を離れると、その課題の盤面と経過時間は捨てる(盤面にカードがあるときは確かめてから)。チャレンジで一覧へ戻ると、そのチャレンジは中断して最初からになる(確かめてから)
- 再読み込みでは、遊んでいる途中の課題をそのまま続ける(経過時間も止まらない)
- 操作は v0.2.1 を引き継ぐ: 手札から盤面へドラッグ、盤面内の移動、盤面の外へ出すと手札へ戻る、手札を選んでから空きマスを押して置く、キーボード(矢印・Enter・Delete・Esc)
- 判定は何度でも押せる。通ったカードを光らせて確かめられる
- 幅 400px で本文が横スクロールしない(盤面は枠内でスクロール)

## 8. 保存

- 状態はこのブラウザの localStorage にだけ保存する。外部へは送らない
- 保存キーは `flowchart-kobo:v3`。旧版のキー(`flowchart-kobo:v2`)は読まずに削除する
- 保存するもの: 課題ごと・セットごとの一番よい記録、遊んでいる途中の課題の盤面と経過時間
- 保存できない環境(プライベートブラウズ等)でも遊べる(記録が残らないだけ)

## 9. 設計

| ファイル | 責務 |
|---|---|
| `app/engine.js` | カード定義・課題・読み取り(parse)・実行(run)・判定(judge)・評価(★)・チャレンジの手札計算。DOM に依存しない |
| `app/index.html` | 画面、盤面の操作、経過時間、記録の保存。単体の HTML として開ける |
| `app/favicon.svg` | ブラウザのタブに出すアイコン |
| `test/engine.test.js` | 読み取り・実行・判定・評価・手札・公開物のテスト(`node --test test/engine.test.js`) |
| `tools/preview-server.js` | 手元で確認するための静的ファイルサーバー(公開には使わない) |
| `.github/workflows/pages.yml` | テストと公開の自動化(§11) |

- 課題データは `engine.js` 内に置く(1 問 = お題・数字・ことば・テストケース・正解例と別解・ヒント・基準枚数・基準時間)
- カードは内部の識別子(例: `if`、`loop`、`print`)と、画面に出すラベル(英語・日本語の添え字)を分けて持つ。課題データ・保存データ・テストは識別子で書き、表示のラベルを変えても壊れないようにする

## 10. 受入条件

| ID | 条件 | 確認方法 |
|---|---|---|
| AC-1 | 全課題(練習 2 問・本編 10 問)の正解例と別解がすべて合格し、別解どうしの並べ方はすべて異なる | ユニットテスト |
| AC-2 | 各課題の基準枚数が、正解例と別解のうち最少の枚数と一致する | ユニットテスト |
| AC-3 | 誤った並べ方は不合格になる(境界の取り違え・計算順の誤り・くり返しの抜け忘れなど、課題ごとに 1 つ以上) | ユニットテスト |
| AC-4 | §4-9 の読み取りエラーを、原因のカードを示して知らせる | ユニットテスト + ブラウザ操作 |
| AC-5 | 計算の優先順位・左から順の計算・切り捨て(マイナスを含む)・比較 3 種・PRINT のつなげ方が §4 どおり | ユニットテスト |
| AC-6 | フリーの ★ 判定が §6.1 どおり(★ 2 と ★ 3 の独立、ヒントを開くと ★ 3 なし、記録が下がらない) | ユニットテスト |
| AC-7 | チャレンジの各セットで、仕掛けを満たす解き方の組み合わせが手札に収まり、仕掛けを無視した解き方の組み合わせは収まらない | ユニットテスト |
| AC-8 | チャレンジで、正解した課題のカードが手札から減り、あきらめた課題のカードは戻る。★ 判定が §6.2 どおり | ユニットテスト + ブラウザ操作 |
| AC-9 | マウス・タッチ・キーボードで、置く・動かす・外す・判定するまでできる | ブラウザ操作 |
| AC-10 | 練習・フリー・チャレンジを通して遊べ、再読み込みしても記録と途中の盤面が残る。旧版の保存データがあっても壊れずに始まる | ブラウザ操作 |
| AC-11 | 幅 400px で本文が横スクロールしない。ライト / ダーク両テーマでコントラスト比 4.5:1 以上 | ブラウザ操作 |
| AC-13 | 命令と流れのカード、`=`・`==` に日本語の添え字が出て、読める大きさで収まる。すべてのカードが §3.2 の仲間ごとの色と描き方(塗り / 淡い地と枠)で表示される | ブラウザ操作 |
| AC-12 | 画面・課題データ・設計書に、前の版の題材・カード文言・得点の数値が残っていない | 公開前の文字列検索(公開しない作業用の環境で実施) |

## 11. 公開

- 公開先は GitHub Pages。`app/` の中身をそのまま公開する(ビルドの工程はない)
- main への push で GitHub Actions がテストを流し、合格したときだけ公開を更新する。プルリクエストではテストだけを流す
- main へは直接 push せず、ブランチからプルリクエストを通して入れる(最初の公開を除く)
- 画面の下に、記録の保存先(このブラウザの中だけ)とフォントの読み込み先、不具合報告先(GitHub の Issues)、ソースコード、作者、ライセンスを載せる
- 作業用のフォルダ(`tmp/`)、テストの実行記録(`generated/reports/`)、開発ツールの設定は公開しない

| ID | 条件 | 確認方法 |
|---|---|---|
| AC-14 | 公開するファイルが作業用のフォルダを指しておらず、作業用のフォルダとテストの実行記録は公開しない。公開しない資料に関わる語句が無い | ユニットテスト + 公開前の文字列検索 |
| AC-15 | `index.html` は単体の HTML として開ける(doctype・lang・文字コード・viewport・title・description・OGP・favicon) | ユニットテスト + ブラウザ操作 |
| AC-16 | 画面の下に、記録の保存先・フォントの読み込み・不具合報告先・ソースコード・作者・ライセンスを載せる | ユニットテスト + ブラウザ操作 |
| AC-17 | main への push でテストし、合格したときだけ `app/` を公開する。プルリクエストではテストだけ | ユニットテスト(設定の内容)+ 公開後の GitHub Actions の結果 |
| AC-18 | 公開前に置き換える文字(ユーザー名・作者名・ライセンス名)が残っていない | ユニットテスト |
