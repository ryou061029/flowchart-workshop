## 1. テストの目的

README に「スマートフォンでの操作は、まだ十分に確かめていません」と書いている状態を解消する。スマートフォンの幅とタッチ操作で、練習・フリー・チャレンジを通して「置く・動かす・外す・判定する」ができ、画面が横にはみ出さないことを言えるようにする。

## 2. 対象範囲

### 2.1 テストする

- 画面: スタート、課題(練習・フリー・チャレンジ)、クリア、チャレンジ結果、確認ダイアログ、ヒント
- 幅: 360px(小さめの Android)、390px(iPhone の標準)、400px(AC-11 の値)、横向き 844×390px
- タッチ操作(課題画面)
  - 手札から盤面へドラッグして置く
  - 盤面のカードをドラッグして動かす
  - 盤面のカードを盤面の外へドラッグして手札へ戻す
  - 手札をタップして選び、空きマスをタップして置く
  - 盤面のカードをタップして選び、「手札に戻す」をタップする
  - 判定する・ヒント・盤面を片付ける・一覧へ戻る・あきらめる の各ボタンと、確認ダイアログのタップ
  - 試しに動かす欄への入力と実行
- レイアウト: 本文が横にスクロールしない、盤面は盤面の枠の中だけで横にスクロールする、操作要素(ボタン・手札)の大きさが 24×24px 以上
- 通し: 練習 1 問を置くところからクリア画面まで、タッチだけで進める。チャレンジ 1 セットを開始して 1 問あきらめ、結果画面まで進める
- 再読み込み: スマートフォン幅で遊んでいる途中に再読み込みしても盤面が残る(AC-10 をスマートフォン幅で 1 ケース)

### 2.2 テストしない

| 対象 | 理由 |
|---|---|
| 実機(iOS Safari・Android Chrome)での操作感(ドラッグの追従、指で隠れる、押しにくさ) | 実機もデバイスファームも手元に無い。Chromium のモバイルエミュレーションで操作の成立だけを確かめ、操作感は実機確認の観点 FC-MOB-M001・M007・M009 として引き継ぐ |
| ピンチズーム・長押しのメニュー・ページのスクロールとドラッグの競合 | エミュレーションではブラウザの既定の振る舞いを再現できない。FC-MOB-M002・M003・M005 として引き継ぐ |
| ドラッグの指を動かしながら離した直後のタップ | エミュレーションではフリングと見なされて直後のタップが抑止される(合成イベントの出し方の問題で、製品側では再現しない)。実機で同じことが起きるかは FC-MOB-M004 として引き継ぐ |
| ソフトキーボードが出たときのレイアウト | 同上(エミュレーションでは出ない)。FC-MOB-M006 |
| ダークモードの見え方 | 色のコントラストは §3.2 で計算済み。見え方の判断は FC-MOB-M008 に含める |
| 性能(描画の速さ・電池) | 今回の目的(操作の成立)の外 |
| 探索的テスト(想定外の操作) | 今回は仕様に書いた操作の成立が目的。必要になれば `freedia-monkey-test-run` で別途行う |
| Firefox・WebKit のエミュレーション | 手元に入っているブラウザが Chromium だけ。WebKit(iOS Safari 相当)は実機確認へ |

## 4. 実施環境

- 手元の確認用サーバー `node tools/preview-server.js app 5178` で `app/` を配信し、Playwright の Chromium をモバイルエミュレーション(タッチあり・モバイル UA・DPR 3)で動かす。公開サイト(GitHub Pages)には触らない
- Playwright は作業用フォルダ `tmp/playwright/`(コミット対象外)に入れる。リポジトリの依存には加えない
- テストデータ: 保存データは空の状態から始める。盤面に置く解き方は練習 1 の正解例(`a = INPUT × 2` → `PRINT a`)と、課題 1 の正解例
